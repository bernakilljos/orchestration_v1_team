## 🚀 Phase 1 — 실구현 대상 (4개, design_web 추가)

**기간**: 1-2개월 | **목표**: 최소 수익화 엔진 + 웹 프론트

### 1.1 `exec_scheduler` ⭐⭐⭐ (최우선)
**이유**: 현재 cron 부재. 모든 정기 작업의 기반.
**규모**: 작음 (~1주)

```
/cron          크론 잡 등록 (YAML 선언형)
/workflow      DAG 워크플로우 정의
/run-now       즉시 실행
/status        실행 중 + 다음 예약
/history       실행 이력·성공률
/retry-policy  재시도 정책 (exponential backoff)
```

**스킬**: `skill-scheduler-idempotency` (멱등성), `skill-scheduler-distributed` (분산 락)
**의존**: `exec_orch`

---

### 1.2 `mcp_social` (YouTube 축소판) ⭐⭐⭐
**이유**: `cost_youtube` 전제 조건. 다른 플랫폼은 후순위.
**규모**: 중간 (~1-2주). 일단 YouTube Data API v3 만.

```
/install       YouTube Data API v3 설치
/auth          OAuth 2.0 (토큰 자동 갱신)
/status        API 쿼터·토큰 만료일
```

**확장 예정** (Phase 2): Instagram Graph API, TikTok, X API v2, Naver Blog, Tistory

---

### 1.3 `cost_youtube` (축소판 3개 커맨드) ⭐⭐⭐
**이유**: 수익화 1번 채널. 가장 현금화 빠름.
**규모**: 중간 (~2-3주). **9개 커맨드 → 3개만**.

```
/yt-research   트렌드·키워드 리서치
/yt-upload     YouTube Data API 업로드 (--dry-run 지원)
/yt-analytics  수익·조회수·시청지속시간 리포트
```

**스킬**: `skill-yt-hook-writing`, `skill-yt-algorithm`
**훅**: `hook-post-upload-24h` (성과 미달 시 SEO 재실행 제안)
**의존**: `mcp_social`, `exec_scheduler`

**후순위로 뺀 것** (Phase 2): `/yt-script`, `/yt-thumbnail`, `/yt-seo`, `/yt-shorts`, `/yt-competitor`, `/yt-comment`

---

### 1.4 `design_web` ⭐⭐⭐
**이유**: 수익화 랜딩·포트폴리오 필수. 기존 design_* 계열 자연 확장.
**규모**: 중간 (~2주). 기본 공통 헬퍼 포함 생성됨.

```
/landing        랜딩페이지 (헤드라인·CTA·증명)
/blog-template  블로그 템플릿 (Tistory·Ghost·Jekyll)
/portfolio      포트폴리오 사이트
/seo-meta       메타태그·OG·JSON-LD 자동 삽입
```

**스킬**: `skill-web-seo`, `skill-web-conversion`
**훅**: `hook-pre-publish-seo` (발행 전 메타·alt·canonical 검증)

## ⚠️ 설계 체크리스트 (모든 신규 플러그인 공통)

- [ ] **멱등성**: 재실행해도 안전한가
- [ ] **에러 복구**: 중간 실패 시 재시작 지점
- [ ] **Rate limit**: 지수백오프 재시도
- [ ] **비용 관측**: 토큰·API·스토리지 로깅
- [ ] **드라이런 모드**: `--dry-run` 옵션
- [ ] **비동기**: 긴 작업은 웹훅/콜백
- [ ] **시크릿 관리**: `.env` 또는 vault. `plugins/` 커밋 금지
- [ ] **로깅 레벨**: DEBUG/INFO/WARN/ERROR
- [ ] **한국 특화**: 네이버·카카오·토스 우선
- [ ] **법적 고지**: 수익 플러그인은 공정위 표시광고법 문구

## 🎯 이 로드맵의 역할

이 프로젝트(orchestration_v1)는 **킷**입니다. 플러그인 실구현은 여기가 아니라 **설치 후 플랫폼**에서 진행.

- **여기서 유지**: `exec_orch` 코어, 플러그인 스펙·템플릿, sync 시스템, 이 로드맵 문서
- **플랫폼에서 실구현**: 각 플러그인의 실제 API 호출·비즈니스 로직 (수익화 프로젝트·Micropolis 등 설치처)

**플랫폼에서 구현할 때의 권장 순서**:
1. `exec_scheduler` (1주) — 정기 실행 기반
2. `mcp_social` (YouTube 한정, 1-2주) — OAuth·Data API
3. `cost_youtube` 축소판 3커맨드 (2-3주) — 1채널 수익 검증
4. 검증 성공 후 Phase 2 진입 결정

**공통 원칙**: 한 번에 1-2개씩. 빈 껍데기 md 금지. 실제 동작 코드까지.
