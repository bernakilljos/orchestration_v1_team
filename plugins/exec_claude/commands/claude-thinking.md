## Context
- 인자: `$ARGUMENTS` (분석할 문제·태스크)
- Extended Thinking = Claude 가 답변 전 내부 사고를 길게 함 (Opus/Sonnet)

## Your task

`skill-claude-thinking` 활성화. 복잡 문제에서 Claude 의 추론 단계를 명시적으로 분해해서 정확도를 높임.

### 언제 Extended Thinking 가 가치 있는가

| 가치 ↑ | 가치 ↓ |
|--------|--------|
| 알고리즘 설계 | 단순 코드 수정 |
| 아키텍처 결정 | 파일 읽기 |
| 디버깅 (근본 원인) | 포맷팅 |
| 비교·트레이드오프 | 검색 |
| 수학·증명 | 출력 변환 |

### Step 1 — 문제 분류

`$ARGUMENTS` 분석 후 카테고리 결정:

```
🧠 문제 분류
  유형: <algorithm | architecture | debugging | tradeoff | math | other>
  난이도: <low | medium | high>
  Extended Thinking 권장: <yes | no | optional>
  이유: <한 줄>
```

`no` 면 → 일반 답변 안내 후 종료.

### Step 2 — 사고 단계 분해 (yes 인 경우)

문제를 5~10 단계로 명시적 분해:

```
1. 문제 재정의 — 사용자 의도 명확화
2. 제약·전제 식별 — 무엇이 주어졌고 무엇이 빠졌는가
3. 후보 접근 3개 생성 — A·B·C
4. 각 트레이드오프 비교 — 시간/공간/복잡도/유지보수
5. 1순위 선택 + 근거
6. 1순위의 약점·실패 시나리오
7. 보완책
8. 최종 권장 + 다음 행동
```

### Step 3 — 단계별 추론 출력

각 단계를 짧은 단락으로 응답:

```
═══════════════════════════════════════
🧠 Extended Thinking — <problem>
═══════════════════════════════════════

[1] 문제 재정의
    <2~3 문장>

[2] 제약·전제
    - <전제1>
    - <전제2>

[3] 후보 접근
    A. <접근1> — 핵심: <one-liner>
    B. <접근2> — 핵심: <one-liner>
    C. <접근3> — 핵심: <one-liner>

[4] 트레이드오프
    | | A | B | C |
    | 시간복잡도 | O(n) | O(n log n) | O(n²) |
    | 구현난이도 | 낮음 | 중간 | 높음 |
    | 유지보수 | 좋음 | 보통 | 나쁨 |

[5] 선택: <X>
    이유: <2~3 문장>

[6] 약점·실패 시나리오
    - <시나리오1>

[7] 보완
    <대응책>

[8] 최종 권장
    → <구체적 다음 행동>
```

### Step 4 — 결과 저장 (선택)

사용자가 "저장해" 라고 하면:
- `docs/2026-04-23/thinking-<slug(problem)>.md` 로 저장

### 안티패턴
- ❌ 단순 문제에 적용 (낭비)
- ❌ 단계 분해 없이 긴 글 (가독성 ↓)
- ❌ 후보 1개만 (트레이드오프 의미 없음)
- ❌ 트레이드오프 표에 정성적 표현만 (수치·복잡도 명시)
